# P8-03 Nonlinear MPC baseline

`mca/control/nonlinear_mpc.hpp` provides a dependency-free generic nonlinear MPC baseline based on direct shooting and projected finite-difference gradient descent.

## Formulation

For a discrete nonlinear model

`x[k+1] = f(x[k], u[k])`,

the solver minimizes

`J = sum(k=0..N-1) l(x[k],u[k]) + V(x[N])`

subject to element-wise control bounds `u_min <= u[k] <= u_max`.

The optimizer initializes the complete control sequence at the midpoint of the bounds by default, computing each midpoint as half the lower bound plus half the upper bound to avoid overflow for large-but-finite same-sign bounds, or accepts `NonlinearMpcOptions::initial_control_sequence` as an optional warm start. A warm-start matrix must match control-dimension × horizon and contain only finite values; values are projected into the configured control bounds before rollout. `shift_nonlinear_mpc_warm_start` advances a previous solution by one control step and repeats the final column when extending the horizon, without modifying its output on invalid input. The solver estimates the objective gradient with finite differences. During line search, if subtracting a gradient update rounds back to the current control (including when the step-gradient product underflows to zero), it probes the nearest representable feasible control in the descent direction with `std::nextafter` before deciding that no candidate can improve the objective. This avoids treating floating-point rounding alone as proof that no descent step exists; the candidate still must produce a strictly lower evaluated objective to be accepted. If subtracting the finite perturbed control values would overflow despite a representable quotient, it normalizes the control interval by the larger absolute perturbed value before forming the quotient; the ordinary denominator and difference-first paths remain unchanged whenever their arithmetic is representable. It first subtracts the finite-difference objective values and divides by the control interval, preserving precision when the difference is representable. If the raw subtraction would overflow, it instead divides each cost by the interval before subtracting, avoiding an intermediate overflow when the resulting gradient is representable. If the quotient itself is not representable, the solver still rejects the non-finite gradient. The solver uses bounded backtracking to accept only steps that strictly reduce the objective. Every candidate is projected into the control bounds; fixed control dimensions (equal lower/upper bounds) are supported with zero gradient for that dimension. If no improving step is found within the configured line-search budget, optimization stops and returns the best accepted sequence. The first control vector is returned for receding-horizon use. `NonlinearMpcResult::iterations_completed` counts outer gradient iterations entered, while `line_search_evaluations` counts candidate trials. `termination` distinguishes exhausting the outer iteration budget, stopping because no candidate strictly improved the objective, and satisfying an optional projected-gradient tolerance. Set `NonlinearMpcOptions::projected_gradient_tolerance` to a finite positive value to enable this stopping rule; zero disables it and preserves the prior iteration behavior. `NonlinearMpcResult::projected_gradient_norm` reports the norm of the bound-projected gradient mapping, scaled by `NonlinearMpcOptions::gradient_step`; this makes the diagnostic invariant to the configured optimization step size for the same local gradient and active-set geometry. This is a practical first-order stopping diagnostic, not a formal KKT certificate for general nonconvex problems. If the multiplication of the finite gradient by the configured step underflows to exact zero while the gradient itself is nonzero, the solver computes the mapping from the local gradient and active-bound geometry instead of treating the rounded projected step as proof of stationarity. Thus an interior tiny nonzero gradient remains visible in the diagnostic, while a gradient pointing out of an active lower/upper bound correctly maps to zero.

## Callback exception contract

`dynamics`, `stage_cost`, and `terminal_cost` are caller-supplied callbacks and may throw. The solver catches both exceptions derived from `std::exception` and non-standard C++ exceptions. A callback exception is treated as a solver failure, not as a convergence or line-search condition. The solve returns `false` and reports the stable failure message `nonlinear MPC callback threw an exception`. The caller's existing `NonlinearMpcResult` remains unchanged because the solver only commits its internally accumulated result after the complete solve succeeds. This transactional behavior applies whether the exception occurs during the initial rollout, finite-difference evaluations, or line-search candidate evaluation.

## Scope and guarantees

- generic state/control dimensions through Eigen dynamic vectors;
- caller-supplied nonlinear dynamics and stage/terminal costs;
- deterministic bounded optimization and line-search iteration counts;
- optional validated warm starts with bound projection and a transactional receding-horizon shift helper;
- non-increasing objective across accepted optimization iterations;
- termination diagnostics (`IterationLimitReached` or `NoImprovingStep`), completed outer iterations, and line-search trial count. `NoImprovingStep` means the configured search budget found no strictly improving candidate; it is not a mathematical convergence certificate;
- support for fixed control dimensions where lower and upper bounds are equal;
- explicit element-wise control bounds;
- finite-value and dimension validation;
- transactional output: an invalid solve leaves the caller's result unchanged;
- callback exception safety: standard and non-standard exceptions from user callbacks become transactional solver failure;
- projected-gradient diagnostics remain nonzero for representable tiny nonstationary gradients even when the gradient-step product underflows, while active-bound outward gradients still report zero residual;
- no external nonlinear-programming dependency.

This is a reference/baseline solver rather than a real-time SQP or interior-point implementation. Direct shooting with finite-difference gradients scales poorly with horizon and control dimension, and state/path constraints are intentionally outside this baseline. Production MPC should consider analytic/automatic derivatives, warm starts, trust regions, state/path constraint handling, and solver-specific real-time guarantees.

Tests cover nonlinear rollout/convergence, objective non-increase under an aggressive initial step, fixed control bounds, invalid line-search configuration, callback validation, and transactional failure behavior. A deterministic receding-horizon regression repeatedly solves, applies only the first control, shifts the previous sequence, and warm-starts the next cycle while checking bounded controls and closed-loop state reduction. Projected-gradient tests cover first-order stationarity at active upper and lower bounds, a fixed control dimension, verify that a nonstationary interior point does not trigger the stopping rule, and verify that the reported mapping norm is invariant to the configured gradient step. Initialization tests cover representable midpoints of large same-sign finite bounds and preserve the caller's result when the initial rollout fails. Gradient regressions cover opposite-sign extreme finite control perturbations whose interval subtraction overflows while the resulting quotient remains representable, large finite objective values whose direct subtraction overflows while their finite-difference quotient remains representable, and adjacent large same-sign costs where difference-first arithmetic preserves the representable quotient's precision. The projected-gradient diagnostic uses a scaled Euclidean norm so large finite components do not overflow during intermediate squaring when the final norm is representable. When multiplying a finite gradient by the configured step overflows, or subtracting a finite step from a finite control would overflow, the projected-gradient mapping selects the bound in the descent direction directly rather than relying on an infinite intermediate and clamp behavior; line-search candidates apply the same explicit bound selection for finite subtraction overflow. When the projected-gradient step product underflows to zero for a nonzero gradient, the mapping falls back to the corresponding local first-order value (or zero for an outward active-bound direction) instead of manufacturing a false stationary residual. A line-search regression exercises a finite control minus finite gradient-step product that would overflow before projection. When backtracking halves its step to zero, it terminates the search immediately because further candidates would be identical; a denormal-step regression verifies that an update rounded to the same control sequence terminates without a redundant rollout; `line_search_evaluations` counts only actual candidate rollouts. The projected-gradient mapping respects box constraints: at an active bound, an objective gradient pointing out of the feasible interval is stationary for the constrained first-order test; a fixed dimension has no feasible descent direction. Callback exception handling guarantees transactional failure for both standard and non-standard exceptions from dynamics, stage-cost, and terminal-cost callbacks. Dedicated P8-40 regressions cover an interior tiny gradient whose step product underflows and an active-bound outward tiny gradient that should still satisfy the projected-gradient tolerance. The benchmark compares cold-start and receding-horizon warm-start solve cost for several horizons.


P8-41 adds phase-specific exception regressions: the initial rollout succeeds, then a user callback throws during a finite-difference rollout or a line-search candidate rollout. Both cases must return the stable callback-exception failure and leave the caller's pre-existing result unchanged.

P8-42 ensures finite-difference probes remain informative when the configured step is smaller than the local floating-point spacing: if `base + h` or `base - h` rounds back to `base`, the solver probes the nearest representable value in that feasible direction using `std::nextafter`. Fixed dimensions and cases with no distinct feasible representable probe still produce a zero gradient for that dimension. A regression starts from a large control value with a sub-ULP finite-difference step and verifies the solver can detect descent and reduce the objective.


P8-43 adds a line-search regression for a representable nonzero gradient whose configured step product underflows: the solver must try the adjacent feasible floating-point control and accept it when the objective decreases. The denormal-step no-improvement regression also checks that an actual adjacent-control rollout is counted even when objective rounding prevents acceptance.
